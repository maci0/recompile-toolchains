# Release readiness: 1.19.0, 2026-11-22

`make images` compares an object's machine and its width with the row for every `arch` and `bits` pair the registry has: a COFF i386, USE32 OMF or PE i386 object under an `x86_16` row fails as `WRONG-TARGET` (only ELF32 i386 also counts for `x86_16`, because ia16-elf writes its 16-bit code under that machine), and the check reads PE executables, ASxxxx `.rel`, xo65, Z80RMF, Amiga hunk and Xbox 360 COFF objects. Every row publishes `arch` and `bits`: the seven that had neither (`bootlin-m68k-glibc-2026.08-1`, `gcc-3.1-1041`, `gcc-4.0.0-5026`, `gcc-4.0.1-5363`, `gcc-4.0.1-5370`, `ido-5.3-linux`, `ido-7.1-linux`) declare `m68k`, `powerpc` and `mips` at 32 bits, `toolchains.py` refuses a row without them, and the `make images` summary counts what it did not check. The ten pins without an immutable source (six release assets under rolling tags, four `ia16-gcc-6.3.0-20260612` packages in a Launchpad PPA pool) are named in the moving-reference test, `docs/ADDING-TOOLCHAIN.md` and the README. The docs name the two readers of `toolchains.json`, rebrew and recompile (CHANGELOG). `toolchains.json` sha256 is `ec871d542d7d76ca637e325a8904c4a17cd1cc8198e621c18b67d58ebc267729`; it differs from 1.18.0 in `arch` and `bits` of those seven rows and in nothing else. No dependency pins changed.

Verification on the release commit's tree, with uv 0.13.6: `uv run --no-sync make lint` (lock consistency, ShellCheck, Ruff checks/format, mypy), `uv run --no-sync make test` (wrapper regressions, 113 Python tests), `uv run --no-sync make verify` (272 compared, 63 new, 27 acknowledged, 0 differ against 07a7268) and `sha256sum -c toolchains.json.sha256` (`toolchains.json: OK`) passed. `uv run --no-sync make pins` passed on the tree the release commit was made from (507 pinned URLs, 0 failing). The Docker smoke gate (`make smoke`) was not run: this release changes no recipe, wrapper or base image.

Images: none was built or rebuilt for this release. `make images` on this machine's `rebrew/` tags: 335 entries, ok 25, ok (branch) 30, MISMATCH 0, NO-SUMS 0, absent 280; compiler binaries of 55 images, 0 failing; object targets of 55 images: agree 54, WRONG-TARGET 0, withdrawn 1 (`msvc-9.0-sp1`), not checked 0. `PREFIX=fx4tc make images` on the 43 images rebuilt for 1.18.0: ok 43, MISMATCH 0, NO-SUMS 0, absent 292; compiler binaries of 43 images, 0 failing; object targets of 43 images: agree 42, WRONG-TARGET 0, withdrawn 1, not checked 0. Not checked, because no image of theirs is on this machine and no recorded object shows their width: the seven `x86_16` rows `borland-2.0-decompme`, `borland-3.1-decompme`, `ia16-gcc-6.3.0-20260612`, `msc-5.1`, `quickc-2.50`, `watcom-2.0-20261001-win16` and `watcom-2.0-win16`; `make images` on a host that holds them settles each. Two limits of the check are stated in its docstring and the README: it cannot tell a 32-bit ELF compiler under the ia16 row from ia16-elf, and ACK objects name no machine. Whether sdcc 4.6.0 writes the `O -m<port>` line the check reads in a `.rel` file was not confirmed on an sdcc image; without the line the object is counted as not checked, not failed.

Deployment: production's recompile runs its compiles on the node's Podman engine with images held in that engine's store; this source release changes no running service and needs no image republished. Consumers that read `toolchains.json` find `arch` and `bits` on every row.
