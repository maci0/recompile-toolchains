# Release readiness: 1.19.1, 2026-11-22

`runtime` states the runner that executes a compile in the image as built: `psyq-4.0`, `psyq-4.1`, `psyq-4.3` and `psyq-4.4` publish `wibo` (their images set `REBREW_RUNNER=wibo` and their wrappers obey it; their recipes named `wine`), and `make test` holds the published `runtime` of every row to the runner its recipe's environment and wrapper select. The CI `smoke` job, red on every run since the hosted runner moved to Docker 29.4.2 on 2026-11-21, probes whether the engine lets the 32-bit wineserver create its socket and runs the Wine cases with `--security-opt seccomp=unconfined` where it does not; its last line counts the cases that ran, ran unconfined, were skipped and failed. `tests/smoke.sh` reads manifest fields through `tests/manifest_field.sh` instead of a Python heredoc. The README names the Docker release that cannot run the Wine images under its default seccomp profile (CHANGELOG). `toolchains.json` sha256 is `5df24837811e3d5c0d22fb3925ca09af3fd34c162f333609b2af3f8a0678643c`; it differs from 1.19.0 in `runtime` of those four rows and in nothing else. No recipe's Dockerfile or wrapper, no base image and no dependency pin changed.

Verification on the release commit's tree, with uv 0.13.6: `uv run --no-sync make lint` (lock consistency, ShellCheck, Ruff checks/format, mypy), `uv run --no-sync make test` (wrapper regressions, 116 Python tests), `uv run --no-sync make verify` (272 compared, 63 new, 27 acknowledged, 0 differ against 07a7268) and `sha256sum -c toolchains.json.sha256` (`toolchains.json: OK`) passed. The smoke job passed in CI on commit 1699895, before the four runtime rows and the field script changed (run 45050065127: 20 cases ran, 3 with seccomp=unconfined, 0 skipped, 0 failed); the tag follows a green smoke run on the release commit itself. `make pins` and `make images` were last run for 1.19.0 and were not repeated: no pin, recipe or image changed.

Images: none was built or rebuilt. The runner of `psyq-4.0` was read from a traced compile in the local `rebrew/psyq:4.0-ps1` (`wibo CC1PSX.EXE`, `wibo ASPSX.EXE`); `psyq-4.1`, `psyq-4.3` and `psyq-4.4` were read from their recipes and wrappers only, since no image of theirs is on this machine. Still not checked for their object width, as in 1.19.0: the seven `x86_16` rows `borland-2.0-decompme`, `borland-3.1-decompme`, `ia16-gcc-6.3.0-20260612`, `msc-5.1`, `quickc-2.50`, `watcom-2.0-20261001-win16` and `watcom-2.0-win16`.

Deployment: production's recompile runs its compiles on the node's Podman engine with images held in that engine's store; this source release changes no running service and needs no image republished. A consumer that treats a `wine` row differently from a `wibo` row (rebrew exports `INCLUDE` and `LIB` and captures the preprocessed source for Wine rows) reads the four PSY-Q rows as `wibo` from this release on.
